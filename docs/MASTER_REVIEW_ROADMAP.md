# Master Review Roadmap

Last updated: 2026-07-26

This is the post-DA28 execution plan. It contains 200 small cuts in 20 system
waves with explicit dependency links. DA26-DA28 remain closed at their written ceilings. A future
control-adoption cut must load the first approved queue into the authority
selector before implementation starts.

## Use contract

- Execute one task or one named batch. A unit test or generated JSON file can
  close only its named cut.
- Keep current HEAD, formal/global, focal, visual/product, source, release, and
  backlog cursors separate.
- `[R]` means research, `[A]` architecture or control, `[I]` implementation,
  and `[G]` evidence gate. Research and docs earn no runtime or score credit.
- Every closeout must link inputs, exact command or route, output artifact,
  revision, failure-path evidence, and the claims that remain blocked.
- A task may split further when one review would mix unrelated owners. Keep
  later owners in their listed cuts.
- Commercial and third-party assets remain out of scope. Use repository-owned,
  generated, or clearly licensed fixtures only.

## Dependency spine

1. DA29-001…010 restore control and proof authority.
2. DA29-011…020 make coverage, browser, performance, and environment evidence
   fit for later decisions.
3. Runtime, product, asset, and scanner waves can then move in parallel where
   their listed dependencies allow.
4. DA29-131…140 may extract shared code only after two live consumers exist.
5. DA29-141…150 turn the proven gates into a repeatable release decision.
6. DA29-151…200 cover the long tail: command/AI/modes, wider MUGEN product
   formats, advanced IKEMEN, Studio authoring, SDK, and deployment governance.

Waves group related owners. A listed dependency takes priority over numeric or
wave order; format, storage, and asset prerequisites can therefore unblock a
task in an earlier system wave.
